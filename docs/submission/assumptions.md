# Допущения и упрощения

Честный список упрощений прототипа для жюри.

## Инфраструктура и данные

- **Нет Alembic.** Схема: `Base.metadata.create_all` + идемпотентный `ensure_columns()` (ALTER при необходимости) и seed при старте приложения.
- **SQLite** в томе Docker `app-data` (`/data/app.db`). Достаточно для демо; не production-grade.
- **Нет облачного деплоя** в проверяемой версии — запуск через `docker compose` на обычном ПК.
- Только **синтетические** персональные и финансовые данные. Реальных ПДн нет.

## Интеграции

- Реестр компаний, финансы, БКИ, каталог продуктов, новости — **локальные JSON-моки** (`backend/app/mocks/data/`).
- Сбой / `unavailable` мока ≠ автоматический кредитный отказ (ветка `manual_review`).
- Неизвестные финданные не подменяются нулями.

## Auth и UI

- Demo-login без signup. Единый пароль всех seed-аккаунтов: **`demo`**.
- Opaque Bearer-токен в таблице `sessions`; на клиенте — `localStorage` (не cookie HttpOnly).
- UI ориентирован на **desktop** (пропорциональный scale); мобильная вёрстка не цель MVP.
- Материалы профиля (локальные файлы на экране «Мой бизнес») не загружаются на сервер.

## Кредитный процесс

- Продуктовое ядро MVP — **обычный оборотный кредит**; витрина показывает 13 продуктов из `products.json`, один конвейер на всех.
- Исходы A–E калиброваны в первую очередь на `working_capital`.
- Платёж считается как **аннуитет** по `rate_annual` продукта (демо-упрощение).
- **Подписание и выдача денег** — демо-финал (`offer_accepted`); реальных денег и ЭЦП нет.
- Содержимое вложений **не распознаётся** (нет OCR).
- **LLM / ML-модели не используются** в MVP.
- История — простой журнал `application_events`, не event sourcing.
- После ответа на уточнение заявка возвращается в `manual_review` **без** автоматического recheck (recheck — отдельное действие менеджера).

## Что намеренно не делаем

- Льготный подбор как ядро, конвейеры всех продуктов как отдельные продукты, залог, смена продукта mid-flow.
- K8s, Kafka, живые банковские API, платные API.
- SMS/email как шаг сценария.
